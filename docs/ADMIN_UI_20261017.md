Couplyo source (`bot/keyboards/reply.py`, `bot/texts/buttons.py`,
`bot/texts/promos.py`, `bot/texts/messages.py`, `services/backup.py`). Work began
at upstream `97cdf77`. Pre-existing uncommitted work in the primary checkout was
preserved; implementation and verification used an attached isolated worktree.

  replacing couple-specific rules. The data panel pairs user lookup/history;
  CSV/cache/crawl utilities have their own Back-navigated submenu. Existing
  functionality and provider registrations are preserved.
- Only the final row of the root administrator reply menu contains Cancel.
  Prompts, lookup results and exclusion inputs contain Back. Stale Cancel text
  in a nested menu cannot abandon its stored input state. Result messages no
  longer append the redundant inline management-home button. Native pagination,
  filters, confirmations and actual actions remain inline.
- All six download switches use fixed text and checked/empty state icons, just
  like the forced-join point controls. Native premium icons preserve state. If
  a checkbox document is unavailable, the Unicode checkbox stays visible rather
  than being replaced with a generic settings/download icon. Old reply labels
  and either checkbox state remain routable after restart.
  Join-point and stored-message switches match the exact normalized label, so
  both legacy decorated labels and the new single-icon labels select the same
  setting. The four additional source-message emoji have native pack priorities
  and explicit semantic fallbacks for sparse catalogs.
- Fresh and cached user-facing file sends, in private chats and groups, carry
  Couplyo's exact add-group label and native group-picker link. Internal storage
  copies do not get that user-facing control. The bot username comes from the

  administrator status. Owner mentions use Telegram HTML entities, and group

  downloader behavior and the existing help links.

## Meaning of the download controls

The per-group link ceiling overrides that group's default rolling-minute quota.
It has an effect only while the group quota switch is enabled. It counts actual
download selections, including another format from an existing menu, and can
also defer fresh link inspection after that allowance has been consumed. Bot
administrators are exempt and do not consume group slots; ordinary group
administrators do not gain that bot-admin exemption.

The file-reception switch pauses downloads for users throughout private and
group chats. The main bot administrator is exempt. This is independent of the
quota/gap switches.

The group-notification switch controls private lifecycle reports to the main
administrator: addition, removal, promotion, demotion and detected repairs. It
does not toggle scheduled group advertising or periodic administrator reminders.

## Full backup and recovery

The Backup menu now calls the root-authorized full export rather than the old
six-table public JSON helper. `pg_dump --format=custom --no-owner
--no-privileges` exports the whole configured database consistently, including
all schemas, future/unregistered tables, all bot accounts, references, settings,
queues and sequences. It does not export PostgreSQL cluster roles or external
files/Redis. Native client tools must support the server version. The default
Compose installation can use its own PostgreSQL container's client when the
host client is absent; this fallback is restricted to the configured local port.
Connection passwords use the subprocess environment and tool stderr is not
returned to Telegram or logs. Native SSL options from the DSN are retained.

One export runs at a time, with a five-minute database-tool deadline. Output is
streamed into a private temporary file, never assembled as a full database-sized
Python byte string. A nonzero exit, timeout or invalid custom header prevents
upload. Cancellation kills/awaits the child. Success and upload failure both
remove the private file after use. Telegram's upload limits still apply.

The legacy public JSON helper/import remains available for older exports. The
panel explicitly explains that full custom archives require native `pg_restore`
with the bot stopped; this change does not execute uploaded SQL through Telegram.

## Verification scope

Workstation tests use an isolated PostgreSQL 16 cluster and Redis, with simulated
Telegram RPCs. The full-backup integration creates two disposable databases,
migrates the source, writes data for two bot IDs, and adds an unregistered schema
and bytea table. The actual new exporter produces the archive. Native
`pg_restore` restores it into the empty destination. Assertions check every
registered application table, both bot accounts, extra-schema data and sequence
continuity. Both databases and the archive are removed afterward.

Focused tests cover all six switches in both directions with Unicode/premium
presentation, sparse icon catalogs, navigation/state recovery, stable message
selection, HTML owner mentions, root authorization, invalid archives, tool
failure/timeout/cancellation, upload failure cleanup and both fresh/cache file
publication for every provider. No live bot message, production database backup
or production-host deployment was performed.

The native PostgreSQL export/restore is verified. Compose fallback command
selection has unit coverage; the workstation Docker daemon was unavailable, so
no container export is claimed. Revisit that live fallback only with the
configured Compose service running. The first broad suite overlapped a separate
SQL test process on the same test database: two reset UI assertions were refused
by the database-wide coordinator guard. An isolated rerun passed all 29 reset
tests without changing application code. Concurrent suites need separate test
databases, or must run sequentially; separate SQL schemas do not isolate those
database-wide advisory leases.

The final collection contains 2,642 cases, exercised in ordered segments and
affected reruns rather than one uninterrupted invocation. The closing segment
passed **1,500 tests**; the final affected run passed **307 tests with zero
skips**, including the real complete archive/restore, all new UI behavior and
provider architecture checks. Ruff lint/format passed for 361 Python files.
The final isolated wheel build passed, contains `services/database_backup.py`,
and excludes environment/session/archive/runtime files. Redis snapshot files
are ignored alongside existing local database backups.
